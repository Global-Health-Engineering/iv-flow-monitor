# hardware/

KiCad 8.x electronic design files for the Dripito monitor PCB —
schematic, board layout, project-local symbol and footprint libraries,
component datasheets, fabrication outputs, and supporting scripts.

## Top-level files

| File | Purpose |
|------|---------|
| `flow_monitor.kicad_pro` | KiCad project file |
| `flow_monitor.kicad_sch` | Schematic |
| `flow_monitor.kicad_pcb` | Board layout |
| `flow_monitor.kicad_prl` | Per-user layout state (machine-local; safe to commit) |
| `flow_monitor.step` / `flow_monitor_full.step` | 3D STEP exports of the assembled board |
| `sym-lib-table` | Registers project-local symbol library `lib/IV_Flow_Monitor_Symbols.kicad_sym` |
| `fp-lib-table` | Registers project-local footprint library `IV_Flow_Monitor_Footprints.pretty/` |
| `fp-info-cache` | KiCad-managed footprint cache |
| `power_analysis.md` | Power-architecture analysis notes |
| `*.json` (schematic_review, pcb_review, etc.) | Generated by the `kicad` analysis skill — do not hand-edit; regenerate |

## Subdirectories

| Folder | Purpose |
|--------|---------|
| [`lib/`](lib/) | Project-local KiCad symbol libraries |
| [`IV_Flow_Monitor_Footprints.pretty/`](IV_Flow_Monitor_Footprints.pretty/) | Project-local KiCad footprint library |
| [`datasheets/`](datasheets/) | Component datasheets (PDFs) for everything on the BOM |
| [`gerbers/`](gerbers/) | Gerber + drill + pick-and-place fabrication outputs |
| [`3dmodels/`](3dmodels/) | 3D model artefacts referenced by KiCad footprints |
| [`scripts/`](scripts/) | Hardware-side automation (logo-to-footprint converter, etc.) |

## Gitignored / build-byproduct paths

- `flow_monitor-backups/` — KiCad's auto-saved timed snapshots
  (gitignored; not part of the design)
- `temp/` — KiCad scratch (gitignored)
- `_autosave-*` — also ignored

## Workflow conventions

- Open and build only via the **KiCad GUI** — no CLI build is configured
  for the PCB. Headless ERC/DRC scripts may be added later via the
  `kicad` skill.
- After every meaningful schematic / layout change, regenerate the
  review JSONs with the `kicad` skill (do not hand-edit them).
- Hand-edits to `.kicad_sch` / `.kicad_pcb` files (e.g. via scripts):
  always test by reopening in the KiCad GUI before committing —
  these files are sensitive to structural regressions that pass a text
  diff.
- New / copied symbols must have the project name populated in their
  `instances` block or KiCad complains on load. Don't use `extends`
  inheritance across hierarchical `lib_symbols` blocks.
